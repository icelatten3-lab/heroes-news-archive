# 키움 히어로즈 뉴스 아카이브

구글 뉴스 RSS에서 키워드 기사를 **3시간마다 자동 수집**해 웹페이지로 보여주는 아카이브.
팀원은 링크로 보기만 하고, **토큰을 가진 사람만** 편집 버튼·메모를 보고 메모·태그·중요 표시를 남김.

## 구성
| 위치 | 역할 |
|---|---|
| `.github/workflows/fetch.yml` | 3시간 간격 정기 회차 (한국시간 00:10, 03:10 … 21:10, 회차마다 4번 시도) + 수동 실행 + config.json 수정 시 자동 실행 |
| `scripts/fetch.py` | 구글 뉴스 RSS 조회 → 포털 경유 기사의 실제 언론사 확인 → 중복 정리 → 자동 태그 → `docs/data/YYYY-MM.json` 에 누적 |
| `docs/config.json` | 키워드·제외어·기본 태그·자동 태그 규칙·언론사 별칭 (여기만 고치면 됨) |
| `docs/index.html` | 웹 화면 (GitHub Pages) |
| `docs/annotations.json` | 태그·중요·숨김 기록 (공개, 편집 모드에서 자동 저장 — **직접 올리거나 덮어쓰지 말 것**) |
| 별도 **비공개** 저장소 `<저장소이름>-memo` 의 `memos.json` | 메모 내용 (토큰 있는 사람만 읽기·쓰기) |

## 처음 설치 (약 15분)
1. **아카이브 저장소 만들기**
   - GitHub 로그인 → 오른쪽 위 `+` → New repository
   - 이름 예: `kiwoom-news-archive`, **Public** 선택 (무료 Pages는 Public만 가능) → Create
2. **메모 저장소 만들기**
   - 같은 방법으로 이름 **`kiwoom-news-archive-memo`** (아카이브 이름 + `-memo`), **Private** 선택 → Create
   - 파일은 올리지 않아도 됨 (첫 메모 저장 때 자동 생성)
   - 다른 이름을 쓰려면 `docs/config.json` 의 `memoRepo` 에 `"아이디/저장소이름"` 적기
3. **파일 올리기 (아카이브 저장소)**
   - `uploading an existing file` 클릭 → 이 폴더 안의 `.github`, `docs`, `scripts`, `README.md` 를 통째로 끌어다 놓기 → Commit changes
   - `.github` 폴더가 빠졌다면: `Add file → Create new file` → 파일명에 `.github/workflows/fetch.yml` 입력 → 내용 붙여넣기
4. **웹페이지 켜기**
   - Settings → Pages → Branch: `main`, 폴더: `/docs` → Save
   - 1~2분 뒤 주소 생성: `https://<아이디>.github.io/kiwoom-news-archive/`
5. **첫 수집 (과거 기사 소급)**
   - Actions 탭 → 왼쪽 `뉴스 수집` → `Run workflow` → `backfill_days` 에 `30` 입력 → 실행
   - 5~10분 뒤 웹페이지에 기사 표시. 이후엔 3시간마다 자동

## 이미 설치한 저장소를 새 버전으로 바꿀 때
바뀐 파일만 하나씩 교체. **`docs/data/` 폴더와 `docs/annotations.json` 은 절대 올리지 않기** (수집된 기사·기록이 덮어써짐)
- 저장소에서 해당 파일 열기 → 연필 아이콘 → 전체 선택 후 새 내용 붙여넣기 → Commit

## 토큰 = 편집 + 메모 열람 권한
- 토큰: GitHub이 발급하는 **이 저장소용 출입증** (비밀번호 대신 쓰는 긴 문자열). 발급은 저장소 주인(또는 협업자)이 본인 계정에서
- 토큰이 있는 사람만: 편집 버튼 보임 · 메모 보기 · 메모·태그·중요·숨김 편집
- 토큰이 없는 사람: 기사 목록·태그·중요 표시만 보임. 편집 버튼·메모는 화면에 아예 안 나옴

### 토큰 발급
1. GitHub → 프로필 사진 → Settings → 맨 아래 Developer settings → Personal access tokens → **Fine-grained tokens** → Generate new token
2. 설정
   - Repository access: `Only select repositories` → **아카이브 저장소 + 메모 저장소 두 개 모두** 선택
   - Permissions → Repository permissions → **Contents: Read and write** + **Actions: Read and write** (`지금 수집` 버튼용)
   - Expiration: 원하는 기간 (최대 1년, 만료되면 새로 발급)
3. 생성 직후 화면에 한 번만 보이므로 바로 복사해 두기
- 저장소가 두 개여도 **토큰은 하나** (발급할 때 두 저장소를 같이 선택)
- 토큰은 사람마다 따로 발급해도 메모는 같은 비공개 저장소에 저장되므로 **토큰 가진 사람 모두가 같은 메모를 봄**

### 지금 수집
- 편집 모드에서 `⟳ 지금 수집` 버튼 → 예약 시간을 기다리지 않고 바로 수집 실행
- 수집 2~4분 + 웹페이지 반영 1~2분 뒤 화면이 자동으로 새 기사로 바뀜 (버튼에 진행 시간 표시)
- 토큰에 Actions 권한이 없으면 안내 문구가 뜸 → 토큰 권한 수정

### 편집 모드 켜기
1. 웹 주소 끝에 **`?edit`** 를 붙여 접속 → 예: `https://<아이디>.github.io/kiwoom-news-archive/?edit`
2. `편집 모드` 버튼 → 토큰 + 표시할 이름 입력
3. 한 번 입력한 브라우저는 다음부터 `?edit` 없이 접속해도 자동으로 편집 모드 (토큰은 그 브라우저에만 저장)
4. 공용 PC에서는 사용 후 `편집 모드 끄기` (저장된 토큰 삭제)

## 포털 경유 기사 (네이트·다음 등)
- 구글 뉴스는 일부 기사를 원래 언론사가 아니라 **포털에 실린 사본**으로 알려줌 (언론사 자리에 "네이트", "Daum" 등)
- 수집할 때 포털 기사 페이지를 열어 **실제 발행 언론사**를 찾아 바로잡음 → 화면에 `스포츠서울 · 네이트 경유` 처럼 표시
- 찾는 순서: ① 페이지 정보(언론사 표시 영역) → ② 기사 하단 카피라이트 (`Copyright ⓒ 스포츠동아`) → ③ 기사 첫 줄 `[스포츠서울 | 기자]`, `(서울=연합뉴스)`
- **다음 기사**는 구글을 거치지 않고 다음 뉴스에서 같은 제목을 검색해 원문 페이지를 찾음 (빠르고 막힐 일 적음)
- 네이트 등 나머지는 구글 링크를 풀어서 찾음 → 구글이 GitHub 서버의 몰아치는 요청을 막기 때문에 천천히
- 한 번에 최대 120건 확인
- 구글이 막으면 그 회차는 멈추고 다음 수집 때 이어서 확인 → 그동안 화면엔 `언론사 확인 중`
- 페이지를 열고도 3번 못 찾으면 `언론사 미확인`
- 처음 적용할 때 쌓여 있던 포털 기사는 몇 번의 수집에 걸쳐 차례로 바로잡힘 (`지금 수집` 으로 앞당길 수 있음)
- 네이버 블로그 등 뉴스가 아닌 글은 수집에서 제외 (이미 들어온 글은 화면에서 숨김)
- 같은 언론사·같은 제목 기사가 원문으로도 수집돼 있으면 포털 사본은 화면에서 숨김

## 자동 태그
- `docs/config.json` 의 `autoTags` 규칙대로, 기사 제목에 해당 단어가 있으면 태그가 자동으로 붙음
- 자동 태그는 테두리만 있는 회색 칩, 편집자가 직접 고른 태그는 색이 채워진 칩
- 편집자가 `메모·태그` 에서 태그를 고쳐 저장하면 그 기사는 직접 고른 태그로 고정
- 규칙을 고쳐 Commit 하면 수집이 바로 한 번 돌면서 **과거 기사에도 새 규칙이 적용**됨

## 기사 / 사진·포토 구분
- 제목 맨 앞 괄호에 `포토`·`사진`·`화보`가 들어간 기사(`[사진]`, `[포토]`, `[MD포토]` 등)는 **사진·포토** 탭으로 분리
- 기본 화면은 **기사** 탭. 탭 옆 숫자 = 현재 기간·필터 기준 건수
- 구분 단어는 `docs/config.json` 의 `photoWords` 로 조정

## 날짜별 보기
- 기간 버튼 맨 오른쪽 `📅 날짜` → 달력 표시 (숫자 = 그날 기사 수, 색이 진할수록 많음)
- 날짜 누르면 그날 기사만 표시. `‹ ›` 로 이전 달 이동

## config.json 항목
- `queries`: 검색 키워드 (여러 개 가능)
- `exclude`: 제목에 들어가면 제외할 단어 (예: 키움증권)
- `tags`: 기본 태그 목록 (편집 중 새 태그를 바로 만들어도 됨)
- `autoTags`: 자동 태그 규칙
- `sourceAlias`: 언론사 이름 바로잡기. 예: `{"m.maniareport.com": "마니아리포트"}`
- `window`: 한 번에 조회할 기간. 기사가 폭증해 로그에 "100건 상한" 경고가 뜨면 `4h` 로 줄이기
- `repo` / `memoRepo`: 비워두면 자동 (`아이디/아카이브이름`, `아이디/아카이브이름-memo`)

## 권한 넘기기
- **편집자 추가**: 두 저장소 모두 Settings → Collaborators → 상대 GitHub 계정 초대 → 상대가 본인 토큰 발급 (두 저장소 선택) 후 사용
- **소유권 이전**: 두 저장소 모두 Settings → 맨 아래 Transfer ownership → 웹 주소가 `<새아이디>.github.io/...` 로 바뀜

## 정기 수집 회차
- GitHub 예약 실행은 시간을 보장하지 않음 (30분~1시간 넘게 늦거나 아예 건너뛰는 일이 잦음)
- 그래서 회차마다 4번 시도: 예) 18:10 회차 → 18:10, 18:40, 19:25, 19:55
  - 먼저 돈 1번만 실제로 수집, 나머지는 "이번 회차 완료" 확인 후 바로 종료 (Actions 탭에 짧은 실행이 여러 개 보이는 건 정상)
- 화면 위쪽 표시: `정기 수집 10/12 18:10 회차 완료 · 다음 21:10 · 지금 수집 10/12 19:42`
  - 실제로 18:44에 돌았어도 **회차 시각(18:10)** 으로 표시, 새 기사가 없어도 회차마다 갱신
  - `지금 수집` 은 정기 회차와 별개로 따로 표시 (정기 회차 이후에 눌렀을 때만)
- 회차가 제때 안 돌면 상태를 그대로 표시
  - 회차 시작 후 20분까지: `09:10 회차 수집 진행 중`
  - 그 뒤 ~2시간 30분까지: `⏳ 09:10 회차 수집 지연 중 (GitHub 대기, 10:25경 재시도)`
  - 재시도까지 다 안 되면: `⚠ 09:10 회차 수집 누락 · 다음 12:10`
  - 최근 24시간 동안 놓친 회차: `최근 24시간 누락 21:10`
  - 누락됐을 때는 `지금 수집` 으로 채우면 됨 (다음 회차도 조회 범위가 6시간이라 대부분 자동으로 메워짐)

## 외부 예약 서비스로 정기 회차 실행 (cron-job.org)
GitHub 예약 실행만으로는 회차가 자주 빠져서, 외부 무료 예약 서비스가 회차 시각에 수집을 실행하게 함 (GitHub 예약 실행은 보조로 남겨둠)

1. **실행 전용 토큰 발급** (기존 편집용 토큰과 별개)
   - GitHub → Settings → Developer settings → Fine-grained tokens → Generate new token
   - Repository access: `Only select repositories` → **아카이브 저장소 하나만**
   - Repositories 탭 → `+ Add permissions` → **Actions: Read and write** 만 (Contents 등은 넣지 않음)
   - Expiration: 최대 기간으로 (만료되면 수집이 멈추니 달력에 만료일 기록)
2. **cron-job.org 가입 → CREATE CRONJOB**
   - URL: `https://api.github.com/repos/<아이디>/<저장소>/actions/workflows/fetch.yml/dispatches`
   - Execution schedule: 사용자 지정 → 매일, 시: 0·3·6·9·12·15·18·21, 분: **12**, 시간대 **Asia/Seoul**
   - ADVANCED → Request method: **POST**
   - Headers
     - `Authorization`: `Bearer <실행 전용 토큰>`
     - `Accept`: `application/vnd.github+json`
     - `Content-Type`: `application/json`
   - Request body: `{"ref":"main","inputs":{"trigger":"schedule"}}`
   - 저장 후 TEST RUN → 응답 **204** 이면 성공 (Actions 탭에 `뉴스 수집` 실행이 생김)
- 분을 12분으로 두는 이유: 정각 직전에 실행되면 이전 회차로 판정될 수 있어서 여유를 둠
- `"trigger":"schedule"` 이 있어야 정기 회차로 기록됨 (없으면 `지금 수집` 으로 표시)

## 참고·주의
- **공개 범위**: 아카이브 저장소는 Public이라 주소를 아는 사람은 기사 목록·태그를 볼 수 있음 (검색엔진 노출은 차단). 메모는 Private 저장소에만 저장
- 메모 저장소가 Public으로 바뀌어 있으면 편집 모드가 켜지지 않음 (안전장치)
- 구글 뉴스 기반이라 네이버에만 노출되는 소규모 매체 기사는 빠질 수 있음 → 필요 시 네이버 검색 API 추가 가능
- GitHub 예약 실행은 몇 분~수십 분 늦게 돌 수 있음 (조회 기간이 겹쳐 누락은 없음)
- 수집이 멈춘 것 같으면 Actions 탭에서 실패 기록 확인 → `Run workflow` 로 수동 실행
